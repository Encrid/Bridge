# What was refused: Budgets

The record of `budgets.md`: `README.md`, *Three layers, three seams*.

## Budgets

Refused: keeping a constant and saying it is arbitrary. No condition brings it back.

Refused: no most, with storage allocating a system's record of its terms when the system registers.
A load allocates as it is - *Nothing is allocated in a phase* - so that alone is no reason; the
reason is that storage would then allocate somewhere other than at create, and what storage holds
would no longer be known from the config. It costs room for `systems` times `terms` whether used or
not, and a module that asks more than the deployment stated is refused, as for `types` and
`systems`. The condition that brings it back is that room measured as a cost, or a host that cannot
state a ceiling for modules it has not seen.

that brings it back is the putting back being shown able to fail.

Refused: allocating at load for however many types and systems a module turns out to have, which is
what this first did: memory that is a stated budget times a number nobody stated.

Refused: a module stating its own counts, which `init` already says by declaring. The condition that
brings either back is a host that cannot state a ceiling for modules it has not seen - and it states

## Nothing is allocated in a phase

Of `budgets.md`, *Nothing is allocated in a phase*.

Refused: a bound on the list of where unloaded modules' settings text was. Nothing has unloaded
enough different modules to need one, and a bound would be a key that says how many module names
a deployment may ever have used. The condition that brings it back is a deployment that unloads
different modules without end, each leaving a string in a row that stays.

Refused: growing on demand, which is what the queue, an observer's list and the block of ids did,
and allocating a dispatch's lists and freeing them on every phase, which is what the scheduler did.
A queue that grew had no bound: a module that asked for changes in a loop took memory until the
process had none, and it was every module's process. The condition that brings growing back is a
phase shown never to be where time matters.

## What running out does

Of `budgets.md`, *What running out does*.

Refused: stopping at the first half that fits, which is what this did. A hundred rows arriving with
room for ninety placed fifty, and forty changes were lost for no reason a module could name. No
condition brings it back.

Refused: working the number out from the free gaps and the table's layout, without trying. It states
how a block is laid out a second time, and again for every storage layout of stage 11. The condition
that brings it back is this search being shown to leave room that matters.

Refused: telling one module, the last to have changed the entity, which is what this did. A module
whose own change needed no room answered for another's, and that other was told nothing of a change
it had lost. No condition brings it back.

Refused: telling only the module whose change needed the room. Storage would have to work out which
change that was, and a module that lost a change with the entity would still not be told. The
condition that brings it back is a module that must not answer for an entity another module made
unplaceable.

Refused: stopping the bridge for every exhaustion, which is one rule and lets one module's `spawn`
take the deployment down - and the entity ceiling recovers by itself when something is destroyed.
The condition that brings it back is a deployment for which an entity left as it was is worse than
not running; it is then a key that deployment states, and not the rule.

Refused: an entry answering zero for the module to check, which is the error code the ABI chose not
to have. The condition that brings it back is an invocation that must go on after an entry it made
was refused.
