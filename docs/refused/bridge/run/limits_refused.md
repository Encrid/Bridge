## What a bound costs

Of `limits.md`, *What a bound costs*.

Refused: a timeout as a second net for a system, which is the cheaper check of the two. Where it
fires is wherever the code happened to be, so a stop by it is the one thing a pass cannot reproduce
- `schedule.md`, *What a pass depends on* - though only in a pass where a module was being stopped
anyway. And the wasm backend arms one timeout at a time, which a lifecycle call needs and systems
running at once do not fit. Against that: the factors above are the worst there is, a loop of one
addition, and nothing has measured the work limit on a system that does real work; and a module that
finds it too dear states none. The condition that brings a system's timeout back is a deployment
that wants a net on a module, has measured the work limit as too dear on that module's own systems,
and accepts a stop that is not reproduced. `plan.md`, stage 17, measures the first half. This
refusal's condition was "record and replay being given up for good", and record and replay had
become a host's.

Refused: counting in the module's own code at loop back-edges, by a rewriter of ours. That is an
instrumenting compiler inside the library, for a gain nobody has measured. The condition that brings
it back is a deployment with work limits that cannot afford the factor above.
