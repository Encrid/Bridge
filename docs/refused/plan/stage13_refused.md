# What was refused: Stage 13

What was weighed in `stage13.md` and refused, each with the condition that would bring it back.

## What a capability is

Of `stage13.md`, *What a capability is*.

Refused, after it had been taken: a capability as a sentence of a document that could be observed
to be false. The edge is the same, outside the library, and the unit is wrong: it makes the list
some hundreds of sentences to be read, tests prose, and misses what is exposed and written
nowhere. No condition brings it back.

Refused: every sentence in bold. There are 313, a script finds them, and about a third are reasons
with nothing to test. No condition brings it back.

Refused: the refusals, and what already points at a case. About 170, and a behaviour that is not
a refusal would never be listed. No condition brings it back.

Refused: the host seam and the module seam, and not the backend's. A backend is written by
somebody outside as a host and a module are. No condition brings it back.

## Where the list lives

Of `stage13.md`, *Where the list lives*.

Refused: the documents alone, each capability pointing at its case where it stands and a script
collecting the pointers. A capability nobody pointed from is a sentence like any other, so the
one failure the done-when names, a capability with no case, could not be found. No condition
brings it back.

Refused: the list, and a pointer at every claim as well, held to each other. A reader would see
the case where the claim is made, and it is some hundreds of sentences changed just before stage
14 reads the documents again. The condition that brings it back is stage 14 deciding the prose
is to carry them.

## What a case is named, and the host programs

Of `stage13.md`, *What a case is named, and the host programs*.

Refused: a program a document, about fifteen. The same names and the same grouping, with fifteen
`main`s and fifteen links for nothing a case needs: each case is a process of its own already.
The condition that brings it back is cases of two documents that cannot share a `main`.

Refused: the five programs kept and renamed for what each stage was about. No case moves, and
the cases stay grouped by when they were written, under other words. No condition brings it
back.

Refused, after it had been taken: a case named for the document that states its capability. The
list is grouped by what is exposed, and names in another order would be two orders for one
thing. No condition brings it back.

## Every refusal

Of `stage13.md`, *Every refusal*.

Refused: the same messages held against the patterns `build.py` expects. A pattern is often a
fragment, so a message can look covered and never be printed, and comparing one pattern with
another is a guess. No condition brings it back.

Refused: refusals listed by hand, rows like any other. It is what let one go five stages with no
case. No condition brings it back.

## Under load

Of `stage13.md`, *Under load*.

Refused: every run six copies, with no flag. The quick run made while working would pay for it
each time. The condition that brings it back is a loaded run that costs no more than a plain one.

Refused: a script of its own that starts the copies. A second place that judges a case, to be
kept in step with the first, and one more thing to remember to run. No condition brings it back.

## Where a name's document is said

Of `stage13.md`, *Where a name's document is said*.

Refused, after it had been taken: the document and the heading under each heading of the list.
47 comments of the headers say it already, checked, and the list would say it again. No
condition brings it back.

Refused: nowhere, the list saying only that it is the documents' to say. A name stated in no
document would be silent, and nothing would fail on it. No condition brings it back.

Refused: the 169 citations that are missing, written in this stage. Stage 14 reads every
document to say what is to be improved, and would write them again. The condition that brings
it back is stage 14 leaving the documents' headings as they are.

## A deployment with no backend

Of `stage13.md`, *A deployment with no backend*.

Refused: left as it was, and unstated. Two counts of one kind with two rules, and nothing that
says why. No condition brings it back.

Refused: left as it was, with a sentence and a case that say such a bridge is created and loads
nothing. A case and a sentence for a bridge nobody can use, and the two rules still. The
condition that brings it back is something a host can do with a bridge before it has a backend.

## What was built

Of `stage13.md`, *What was built*.

Refused: a constant said with the key or the argument it is a value of, a line in the list in
the place of a case. It was built, for 36 constants, and taken out: it is an exception to "a
case named for it" that the done-when does not have, and each of the 36 has a run that turns on
it. No condition brings it back.

Refused: a case's name on the command line and another word in the program's table. One thing
with two names, and a failing case found in two steps. No condition brings it back.

Refused: the functions of the five programs moved one by one into a file for each exposed name.
A file is what a set of cases shares, a module they load and how it is stated, and that is not
one exposed name's. The files are named for what their cases are about, and the list is where a
name's cases are found. The condition that brings it back is a reader who looks for a case by
its file and not by its name.

Refused: a backend of the tests' own with all eighteen entries, for the two cases that need a
backend to refuse. Thirteen entries nobody calls. The native backend is linked again with the
one object that differs, as it was for the case of another seam.
