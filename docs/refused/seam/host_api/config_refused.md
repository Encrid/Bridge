# What was refused: Config

The record of `config.md`: `readme.md`, *Three layers, three seams*.

## No unaccountable values

Of `config.md`, *No unaccountable values*.

Refused: one value for both, which is what this had, under two names. `spawns` given the name of "no
limit" compiled and meant "none", and every negative number was taken for -1. The condition that
brings one value back is a key that takes both senses.

Refused: a boolean, left alone meaning false, which is what these were, on the ground that false was
"the off or the safe side for all six". It is not for `pinned`: a module that needs the thread that
loaded it, and was not said to, runs on any. And it was the one kind of key that meant something
when nobody had stated it, against the paragraph above. No condition brings it back.

Refused: an enum for each key, eight names for four answers. The condition that brings it back is a
key that gains a third answer.

## A module's own settings are a component

Of `config.md`, *A module's own settings are a component*.

Refused: a component named by convention, which is a name Bridge-ASM700 would be inventing -
`no_builtins.md`, *No builtins*. No condition brings it back.

Refused: marking it at `declare`, which would have `kind` say two things. The condition that brings
it back is a module that needs more than one settings component.

Refused: keys that name their component, so that any could be seeded - more than seeding is for,
since a module can fill any row itself in `init`. The condition that brings that back is a module
with two settings structs that do not belong in one.

Refused: taking any struct of two integers for text, which would write an offset into somebody's
width and height. No condition brings it back.
