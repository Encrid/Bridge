# Decisions

This document gives the steps of a decision of the project.
A decision goes through each step, in this order. A step that does not apply to the decision tells why.

## The steps

| Step | Content |
| --- | --- |
| 0. Where it sits | The problem at each level of context that it concerns, what a solution gives, and why the decision is relevant. |
| 1. The problem | The parts of the problem. |
| 2. What is written | What the documents of the project already say about the problem, quoted. |
| 3. References | How other people solved this problem. A reference gives knowledge of the problem and of the ways to solve it. It is not a direct solution. Each reference has its link or its path. |
| 4. The options | Each option, with its pros, its cons and what it gives in the end. The current state is an option. |
| 5. Overlap | Whether the project did this work already, in a decision, a part or a document. Whether two things answer one question without a clear gain. |
| 6. The needs | How each option meets each need of `docs/contributing/needs.md`, and other aims when the situation needs them. |
| 7. Tailor | Whether the project can make an option that fits its needs and its context better. |
| 8. Conclusion | The chosen option. For each other option, the condition that brings it back. |
